Ajo Mercy design lab

Eight directions: four for the public site, four for the admin surface. Each one is a different answer to what the product is, not the same layout in a different colour. Open them, throw away the ones that are wrong, and tell me which parts of which to keep.

Standalone HTML and CSS. No build step, no framework.
All content is placeholder. No statistic, testimonial, business or supporter here is real.
These files live outside the app, so nothing here can ship by accident.

What every direction refuses

  • No dark neon, no glowing blobs, no glassmorphism, no gradients at all in any of the eight files
  • No Inter and no Roboto. Four different type systems across the four directions
  • No tiny uppercase eyebrow labels floating above oversized headings
  • No em dashes in interface copy
  • No grid of six identical feature cards, and no card nested inside a card
  • No hover animation that does not reveal an action or mark a target

What every direction has to carry

  • The platform never holds, escrows or transfers funds, stated where money is implied
  • Selection is not confirmation. Visible in the public flow and enforced in the admin one
  • Registering guarantees nothing, said plainly rather than buried
  • Selection counts are never published. No popularity contest
  • Numbers that have not happened yet render as a dash, never a hopeful zero
  • Private fields are shown as withheld rather than silently omitted

Public site

FOUR DIRECTIONS
A

The Register

An ajo is a contribution ledger, so the page is one. Businesses are numbered entries in a ruled table you can read down and compare across, not tiles you scan. Structure comes from hairline rules and column alignment. There is not a single rounded card in the file.

Type Newsreader, Archivo, Spline Sans Mono  ·  Colour aged paper, ink, ledger red, forest

Best if you want the site to feel like a public record that happens to be online. Costs you photography. A table gives businesses less room to be beautiful.

B

Market Day

The loud half of the voice. Flat saturated slabs drawn from Nigerian market signage and adire block colour, heavy display type, hard black borders and offset shadows. The moving band across the page repeats the one sentence that matters, so the repetition is the point.

Type Archivo Black, Karla, DM Mono  ·  Colour indigo, market red, cassava cream, palm green

Best if the site has to survive arriving cold from a viral post and be recognisable in a screenshot. Costs you gravity. This is the hardest direction to keep sober as the story gets serious.

Open direction B
C

Dossier

The restrained half. If verification is the product, the page should look like what verification produces: a case file. Numbered sections, a persistent metadata rail, mono field labels, and black redaction bars showing the fields the platform checks and deliberately never publishes. The redaction device is the argument.

Type IBM Plex Serif, Sans and Mono  ·  Colour cool paper, near monochrome, one stamp red

Best if trust is the thing you have to win before anything else. Costs you warmth. It is a serious page about people, and it risks reading as bureaucratic.

Open direction C
D

Kiosk

The page is a browse surface, not a brochure. Search and filters sit above the fold and the argument for the platform lives underneath the first screen of results. The grid varies its rhythm on purpose: a wide lead item, an in flow explainer answering the question a browser has at that exact moment, then the run. Mobile gets a thumb reachable action bar.

Type Fraunces, Manrope  ·  Colour bone, charcoal, ochre, forest

Best if most visitors arrive wanting to see people, not read a pitch. Costs you the story. The origin and the verification argument both drop below the fold.

Admin surface

FOUR DIRECTIONS
A

Ledger desk

Reviewing is reading rows and comparing them, so the whole surface is one aligned ledger. Counts are a ruled band rather than four tiles. The confirmation pipeline is drawn inline as a five stage strip, and the CONFIRM guard appears in place rather than in a modal.

Shape text rail, ruled band, dense tables, keyboard hints

Best if the team lives in this screen all day. Costs you onboarding. Dense tables assume you already know the job.

Open admin A
B

Review queue

There is no dashboard at all. A reviewer's day is one task repeated, so the product is the task. Three independently scrolling panes: what is waiting, the application itself, and the decision rail with a verification checklist and the note that goes into the applicant's email. You land already working.

Shape three pane inbox, no metrics, decision rail always visible

Best if throughput on applications is the bottleneck. Costs you oversight. Nobody running the whole operation can see it from here.

Open admin B
C

Case file

A decision that changes someone's life should not be taken from a row in a list. One application fills the screen as a document. Evidence sits in the margin where you can check it against the prose. Private fields stay redacted behind an "open and log" button, because opening them is itself an audited act. The decision bar follows you down the file.

Shape single document, margin evidence, sticky decision bar, provenance trail

Best if you want every approval to be considered and defensible. Costs you speed. It is the slowest of the four by design.

Open admin C
D

Ops board

One screen answering "what needs me today", ordered by what it costs someone if it waits. Decisions first as wide rows, then the support pipeline with the confirmation gate drawn as a physical barrier, then the health of the machinery: email delivery, how long people have been waiting, abuse signals. Every bar is labelled. Nothing is a decorative chart.

Shape stacked bands, consequence ordering, labelled bars, audit stream

Best if one person is accountable for the whole operation. Costs you focus. The actual reviewing happens one click away.
